Area screen — kebi://area/{key}

What an area link opens: the summary kebi wrote, what it is good for, and the places you already have there. Backed by GET /v1/areas/{key} → { profile, places, user_data } — the profile is global and generated once on first open, the place list is per-user and computed per request. Every element on this screen is backed by data that already exists or by the profiler call itself: no new fields, no centroid, no per-place rationale.

Rules this screen commits to

  • The summary is the hero. Never clamped, never behind more — it is the one thing on the screen only kebi could have written.
  • No save. Read only, so no TopPill — region interest keeps flowing through ADR-135 signals.
  • Every ancestor opens. The breadcrumb is areas, not decoration — and with siblings gone it is the screen's only way out.
  • Nothing generated per user. The whole screen is the global profile plus a join against your saves. Two users on the same area see the same words.

Still open

  • No way to ask from here. With the dock gone the screen is a dead end — back to chat is the only exit. If the standard kebi FAB belongs here, it is a one-line addition.
  • Empty saves. "your places here" is the only list left; at an area with no saves the screen is summary + chips and nothing else.
  • Country scope. At id, "your places here" is the wrong shape rather than a longer one — a country's children are cities.
  • Back stack. chat → area → place → back is three hops; PLACE_ORIGIN_CHAT is a one-hop marker.
