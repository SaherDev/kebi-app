Area screen — three layouts for kebi://area/{key}

Today an area link renders underlined and tappable and does nothing — useOpenChatVenue returns early on any kind that is not venue. Making it open reverses ADR-136's "areas are context for a sentence, not somewhere to go", so the screen has to earn the reversal. Backing shape mirrors the place screen (ADR-151): GET /v1/areas/{key} returns { profile, places, user_data }, where profile is global — generated once on first open, shared by every user — and places / user_data are per-request and personal. All three options render the same payload; they differ in what the screen is for. Key is hierarchical (id → id/bali → id/bali/canggu), so every level opens and content thins as scope widens.

A · profile-first — the place screen's twin. Same skeleton, same order: eyebrow, title, meta chips, prose, chips, list. An area is a place-shaped thing you read. zero new grammar; venue and area feel like one species. the ask bar is a dock at the bottom — easy to read past.

Constant across all three

  • No save. Areas are read + ask only — region interest keeps flowing through ADR-135 signals. So the TopPill (edit / •••) is absent, exactly as it is on an unsaved place.
  • Never empty. The profile is generated on first open and mixes durable claims with the model's own geography knowledge, so a brand-new area still opens with a paragraph.
  • Global half / personal half. Prose and best-for chips come from the shared area row; the place sections are computed per request and are the only part that differs between two users.
  • Every ancestor opens. The eyebrow is a breadcrumb of areas, not decoration — id/bali/canggu → bali → indonesia, each its own screen.
  • Saved-first, then taste-ranked. A dot (A) or a section split (B, C) — the ordering rule is the same, only the labelling differs.

Open, and deliberately not answered here

  • Country scope. B's place list at id is not a longer list, it is the wrong list — a country's children are cities. If B wins, that section needs a second shape, not a cap.
  • Back stack. chat → area → place → back is three hops; PLACE_ORIGIN_CHAT is a one-hop marker. Areas make that path ordinary.
  • Self-reference. An answer from the area's own ask bar can contain a link to the area you are standing in. Push, no-op, or replace.
