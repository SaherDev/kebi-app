area — loading, empty, error

kebi-app · apps/mobile/src/app/area.tsx · ADR-153 · applies the kernel

The area screen is read-only and arrives from a link — a chat rail chip or a library section header. That matters for its states: you tapped a name and expect that name, so the wait should show the name's frame, and a failure must not leave you on a screen with no idea what you tapped.

Today it is one if: status !== 'ready' renders a centred spinner, or one line of muted grey text for every failure with no retry at all. The body section is hidden whenever it's empty, so a real area with nothing saved in it just ends after the chips.

Body returns null when the section is empty or absent — so an area you've never saved in ends abruptly after the chips. area, decided

1b — the title is real from frame one (the link already carries name + emoji), everything the server owes shimmers in place, static eyebrows stay solid.

2b + 2c — an area with nothing of yours keeps its section header and states it in one muted line naming the area; a dead link gets its own screen with a way back and no retry, because retrying a 404 is a lie.

3b + 3c — a failed load keeps the title, names the area in the error, and freezes the frame under a retry line. A late summary is not an error and never renders one.

One new rule falls out of this screen and generalises: never let "empty", "failed" and "still loading" collapse into the same pixels. That's the actual bug on area today — all three are the absence of content.
