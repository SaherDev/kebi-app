options for the curator write surface · ADR-112 (can_curate) + ADR-121 (knowledge) · design only, nothing built

the backend already takes the write: POST /api/v1/knowledge/curate, gated by the can_curate token claim, body is free prose plus an optional location hint. kebi does the structuring — your paragraph comes back later as claims, the same insider notes that render on the place page. so the whole design problem is: what does writing feel like, and what is the prose attached to. the entity anchor below assumes the contract gains a real place_id / area_id — you said that change is fine.

can you delete a note? — 3 options

the flow has no undo and no review, so a claim that came out wrong lives forever — and this page is where you'd discover it. that makes delete the last open safety question in the feature.

two things are fixed before we start. the gesture already exists: these rows are quote rails, long-press is the app's per-item action gesture, and ContextMenu is generic. and the system dictates the aftermath — destructive actions are optimistic, always toast with undo for 5s, and restore the row on failure. so delete brings a toast back, but for the delete, not the write: you're undoing something you just did on purpose, not chasing an extraction you never saw.

what kebi needs — the gap list. measured against the contract as it stands today (POST /v1/knowledge/curate takes {text, location_hint?} and returns {claims_written, claims[]}, where a claim is {scope, entity_name, claim, tags[]} and scope is country | city | neighborhood):

1 · a venue scope. the biggest one. CurateScope has no place value — curation today can only be geo-scoped, so doors a and d, which anchor to a specific venue, have nothing to write to. everything else here is small next to this.
2 · an entity anchor on the request. place_id from a venue's key, area_id from an area's uri token — the two kinds identify differently and the raw key is unusable for areas.
3 · an id on CurateClaim. the write response returns claims with no id, while the read side (PlaceNote) has one. without it a returned claim can't be mapped to anything — which blocks delete entirely.
4 · a retract path. DELETE one claim by id, for the long-press delete (§5).
