about you · getting around — loading, error

kebi-app · about-you.tsx + getting-around.tsx · ADR-054 · applies the kernel

The two form screens share one shape (read on mount → edit → save → refreshSession) and one real hazard. Their load already fails soft with a toast, and the code says why:

// Fail soft: an empty form that saves would erase a block we failed to read

The comment is right, but the screen doesn't act on it. After a failed read you get an empty, fully editable form with a live save button — so one tap writes emptiness over data that was never actually gone. And these blocks feed the chat's reasoning, so wiping them degrades every answer afterwards.

the two forms, decided

1b — hero, lede and field labels never wait; three shimmer blocks in the inputs' exact heights; no save button until there's something valid to save. Retires the app's last ActivityIndicator.

2b — and this one is a bug fix, not a polish pass. A failed read must leave frozen skeletons, no editable fields and no save button, with "they're safe — this form just can't show them yet" and a retry. Today's empty-but-saveable form can silently overwrite a real profile, and because these blocks feed chat, every answer afterwards quietly gets worse.

3a–3c — the button becomes spinner + "saving" while the PATCH and the token refresh run (a spinner inside a button is fine: it marks an action, not content), a failed save keeps the form and adds retry to its toast, and the success confirmation lands on settings where the row has already flipped to "set".
