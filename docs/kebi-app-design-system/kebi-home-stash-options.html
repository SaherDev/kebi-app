sorted by real distance, ignoring area boundaries — the meta line trades area for time away. the sharpest answer to "where to next?", and the most expensive: kebi declined a distance sort (the cursor would have to carry the origin), so this needs new backend work.

what each costs

a is the only one buildable today: ?area= already exists, and the Library hook already resolves the device's area. It also keeps the card's shape, so it is a change of which rows, not a redesign.

b needs nothing new either — the distribution endpoint is already fetched — but it makes home a second Library rather than a shortcut into it. c needs a distance sort kebi has explicitly declined for now.

one caveat for a and b: matching "where you are" to an area is unreliable by name — the device reports Kuta Utara where the saves say Canggu. The Library already orders by country code for exactly this reason; a badge that names the area needs kebi to resolve coordinates to an area key, which is the parked "you're here" request.
