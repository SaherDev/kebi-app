picker sheets — country · maps

kebi-app · country-picker-sheet · maps-chooser-sheet · applies the kernel

Two sheets that offer a list of choices. Neither loads anything — the country list is a shared constant, the maps targets are built from the place we already hold — so neither has a loading or a failed state, which is worth stating rather than designing.

Between them they have one built empty state and one missing one: the country picker already answers a search with no matches (aboutYou.countryEmpty), while the maps chooser has no answer at all for a place with nothing to open — no coordinates, no address, no provider id. buildMapsTargets returns an empty array and the sheet renders an empty box.

1 · country picker a filtered empty that already exists

The kernel's filtered-empty rule: echo the query, offer the undo, nothing else — no ghost rows, no mascot. The picker is close already; the question is whether it says the same words the library's search empty does.

picker sheets, recommended

1b — the country picker's no-match says exactly what the library's search empty says, query echoed and clear search offered. One filtered-empty sentence for the whole app.

1c settled — neither picker has a loading or a failed state, and that is the answer, not an omission: both read data the app already holds.

2b + 2c — the maps chooser filters to apps that are actually installed, and falls back to one line when there is nothing to open, reusing the bare-place sentence. Neither is a state a healthy place reaches; both stop a sheet from ever rendering blank.
