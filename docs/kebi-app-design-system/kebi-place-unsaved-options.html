Place screen — unsaved state (ADR-151)

GET /v1/places/{place_id} now opens any catalog place, saved or not, and returns the same { place, user_data, claims } shape a library row already renders — with user_data: null when the caller never saved it. That null is the screen's "offer save" signal. So this is not a new screen: it is the place screen with the user-state layer absent, plus one save action. Three options for where that action lives.

A · filled pill in the action row — the primary variant of the .service-btn the screen already has, first in the map/share row. no new layout, reads as the screen's verb.

Behaviour

Save is POST /v1/user/places { place_core_id } — idempotent, so a double tap is harmless, and it emits the strong saved_recommendation taste signal exactly once. Success toasts and flips the screen in place. 403 save_limit_reached routes to the existing upgrade toast. Saved-only affordances stay hidden rather than auto-saving on tap: a note tap should not silently create a library save, and a limit error mid-gesture fails in a confusing place.
