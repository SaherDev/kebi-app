plans · billing — loading, error, unbuilt

kebi-app · plans.tsx + billing.tsx · applies the kernel

Plans renders instantly from PLAN_CONTENT — the cards are local constants, so nothing about them waits. One thing does: profile.plan, which decides which card is yours. Until it lands, every card looks equally available, and the tier the user is already paying for offers to sell itself to them.

Billing is a stub. The whole screen is <ScreenTitle title="billing" /> — a heading on an empty page, reachable from settings. It needs the one state the kernel doesn't cover: a screen that isn't built yet.

plans and billing, decided

1b + 1c — plan names, prices and features are constants and paint instantly; only the three CTAs shimmer, because only they depend on profile.plan. If the profile never arrives, the plans stay readable but every CTA is disabled behind one warn line: read yes, write no.

2a–2c — the chosen card takes its outline optimistically while the button shows spinner + "switching" and the others dim; a failure rolls back and its toast gains a retry; the current card never shows a buy button. A money screen should look boringly unchanged when nothing changed.

3b — billing names the three things that will live there, points at the plans screen, and drops the empty ••• menu. It's the app's only unbuilt state, and the rule it sets is the same one everywhere else: say which of the four things is true — loading, empty, failed, or not built yet — and never let one of them wear another's clothes.
