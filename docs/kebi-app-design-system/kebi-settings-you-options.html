Settings after ADR-054 — where the about-me and the movement modes live

The gateway now holds two things it never held before: an about-me (call_me, home_country, about, stored whole in one field) and a movement profile whose modes kebi ignores until a human picks them (source: "user"). Until a screen writes them, every user is a seeded default — kebi guesses wide and nobody is capped, which is correct but silent. Three readings of the same two payloads. home_country must be a picker, never a text field: a country name is a 400 at the gateway edge.

Constant across all three

  • The country is a picker, never a field. A free-text country is a 400 at the gateway (@IsISO31661Alpha2) — the picker is what makes alpha-2 true by construction, not a nicety.
  • The about-me writes whole. One PATCH /user/about-me carrying all three fields; an omitted field is cleared, not preserved. Every option therefore has exactly one save for that block, and says so where the user can see it.
  • Clearing is a real state. Empty call_me falls back to the account name; empty about stores null, so nothing the user erased comes back as prose they seem to have written.
  • Modes are a capability, not a location. The copy is "what you can use", never "what's available here" — kebi pairs the capability with the city's density itself.
  • Saving is what makes it yours. The write is the only thing that sets source: "user". Before it, kebi deliberately guesses wide; after it, it honours the modes exactly — which is worth saying in the UI, since the change in behaviour is otherwise invisible.
  • Nothing is stored by kebi. Worth one line of copy: this is read at the start of a conversation and outweighed by what you actually do — except a stated restriction, which is a hard constraint.

Decided

  • A wins — two rows, two screens, one endpoint each.
  • The pencil goes. The profile block's edit button (and EditNameSheet) is removed: it wrote the account display name, which would have put two name editors two rows apart writing to two stores. "about you" owns the name now, and the profile header renders call_me ?? account name — so editing call_me visibly renames you everywhere. The account name keeps its signup seed and is no longer directly editable; PATCH /user/profile stays but goes unused.

Open, and deliberately not answered here

  • The refresh lag. Both blocks ride the token claim, so a save reaches kebi on the next token refresh. The name edit already forces one (supabase.auth.refreshSession()) — these should too, or the user sends a message and kebi hasn't heard the news.
  • Prompting the unset. Nobody has movement set today, and nothing asks. A one-time nudge — after a turn where distance mattered — would do more than any of these screens, and belongs in chat, not settings.
  • The reach words. "keep it close / normal / i'll travel" is one reading of compact|normal|far. It could as easily be a distance in km, which is more honest and less voice-y.
