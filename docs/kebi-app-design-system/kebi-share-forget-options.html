share & forget — what the user actually sees

kebi-app · ios SavetoKebi extension + apps/mobile home · options, nothing locked

today a TikTok share cold-boots the whole app — splash, auth gate, home's three fetches — just to raise a save sheet the user came to dismiss. the goal instead: share, forget, and meet the results later.

two hard constraints shape every option here. the extension cannot hold the request — extract is synchronous and takes ~30–60 s on a cold video URL (api/extract.ts), and iOS kills a share extension seconds after it completes. and nobody is present when it lands, so a failure can't be a toast — today's unsupported_url and save_limit_reached toasts would fire into an empty room.

so this page decides two moments: the share, and the next open.

the user is in TikTok. they hit share, they tap Kebi. from here Kebi owns at most a second or two before iOS takes the screen back. the only question is whether we spend it.

shares get their own screen with a full history — every link, when it came, what became of it. the most capable, and the most expensive: a new route, a new data model, a badge to maintain. it also makes shares a separate thing to process, which is the opposite of forgetting.

why a

a is the only option that survives both architectures. if we build the cheap version — the extension queues to an App Group file and the app drains it on next open — the work genuinely starts when the user arrives, so the card opens with working rows that resolve in place over a few seconds. if we later move to a server-side pending enqueue, the same card opens with everything already landed. same component, no redesign, and the design never lies about which one is running.

b and c both leave failures homeless, and failures are the whole reason this surface exists — a save that worked needs no announcement, a save that didn't does. c is the right shape if shares later gain volume (dozens a week, a real history worth scrolling); today it builds a screen to hold four rows.

the dismiss is load-bearing. the card must be gone for good once tapped away, or it becomes a second inbox by accident — which is c, arrived at without deciding to.

what we must not ship
today's toast, into an empty room

the current failure path (save-sheet-context.tsx) — a toast with a try again that reopens the sheet prefilled. it assumes someone is watching. in a forget-flow it fires while the user is in TikTok, auto-dismisses, and the link is silently gone. this is the single behaviour that has to change no matter which option wins.
