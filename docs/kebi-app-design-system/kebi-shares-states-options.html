shares — loading, empty, error

kebi-app · apps/mobile/src/app/shares.tsx · ADR-048 · applies the kernel

Shares is the best-covered screen in the app and needs the least from this pass. Its rows already have all three states by design — working shimmers, failed shows the reason plus a retry mark, landed becomes a place row — because that was the whole point of kebi-share-retry-options.html.

Two things are missing. There is no screen-level loading state (rows come from local storage, so they're there instantly — worth confirming, not designing), and the empty state is one grey line on a screen most users reach before they have ever shared anything, since it's linked from settings.

1 · nothing shared yet the only real gap on this screen

Reached from settings before the first share, or after SHARE_HISTORY_DAYS forgets an old one. There is no in-app way to share into kebi — it happens in TikTok or Instagram, through the iOS share sheet — so this empty state has no button it could possibly offer. It can only explain.

shares, decided

1b — ghost share + the one-line instruction. The ghost does double duty: it shows what a landed share looks like and that one link can become several places, which is why this screen groups the way it does. No add-row and no button, because sharing happens in another app.

2a–2c unchanged. The row states were designed properly the first time and already match the kernel — the working skeleton sits in the landed row's exact geometry. Clearing lands on the same empty state as never having shared, and there is deliberately no screen-level loading state, because the data is local.

One thing to carry into the settings file: this screen is linked from there, so a user can arrive having never shared. The empty state is the first thing they read about the feature — which is why it explains rather than apologises.
