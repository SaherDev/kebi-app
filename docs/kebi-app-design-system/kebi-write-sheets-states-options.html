write sheets — save · curate · note

kebi-app · save-sheet · curate-sheet · note-sheet (+ their contexts) · applies the kernel

Three sheets that take typed words and send them somewhere. All three close optimistically and report the outcome as a toast, which is right — you should be able to save a place and keep moving. The question is only what happens when the write fails after the sheet is gone.

The save sheet already answers it well: its failure toast carries try again, which reopens the sheet with the text still in it. Curate and note don't. Curate does keep the draft (// Clear only on success, so a failed write leaves the prose recoverable) — but nothing tells the user, and nothing offers the way back, so a recoverable draft is recoverable only by accident.

write sheets, recommended

1b + 2b — every failed write says "kept" and carries try again that reopens its sheet with the text intact, on the same anchor. Curate already preserves the draft in code; note needs to start, and both need to say so. That makes one vocabulary across all three sheets, with the save sheet — which got there first — as the model.

Not doing 1c (auto-reopen): it cancels the optimistic close, which is the reason these sheets feel fast. Not doing 1d (draft chip) yet: a new component and a new lifetime for a failure we have no evidence is common. If the retry toast turns out to get missed, that's the next step.
